## 1.2 方案对比（存在多实现的关键项）

### (A) 公式引擎实现
| 方案 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- |
| `expr-eval` 受限模式 | 上手快 | 仍属表达式求值，需禁用危险函数；扩展性一般 | 快速交付 |
| `mathjs` 沙箱 | 函数多 | 体积大、需严格 `import` 白名单 | 函数丰富场景 |
| **自研递归下降解析器（推荐）** | 完全可控、零注入风险、易加 CHECKSUM 等定制函数、易做循环依赖检测 | 需自写词法/语法 | 本系统 |

> **推荐**：自研递归下降 + 运算符优先级（Pratt）解析器，函数表注册式扩展，AST 求值，天然杜绝 `eval`/代码注入。

### (B) 流水号并发安全
| 方案 | 优点 | 缺点 | 推荐 |
| --- | --- | --- | --- |
| `SELECT ... FOR UPDATE` 逐条分配 | 简单、绝对不重号 | 高并发批量逐条加锁，吞吐低 | 小批量 |
| **号段预分配（推荐）** | 批量一次性预占 [cur, cur+N)，内存分配，DB 仅更新游标，吞吐高 | 进程崩溃可能丢号段（可配回滚策略） | 大批量 |
| Redis INCR + Lua | 极快 | 与 DB 主数据一致性需双写 | 备选 |

> **推荐**：DB 行级锁持有号段游标 + 一次性预分配 N 个号；批量打印只锁一次。回滚策略可配（回滚号段 / 消费号段）。

### (C) 画布引擎
| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **Konva.js（推荐）** | React 友好、声明式、自带 Transformer、100 元素流畅 | 富文本需自绘 |
| Fabric.js | 序列化完整、交互成熟 | React 集成偏命令式、样板多 |

> **推荐 Konva**：与 Zustand 状态驱动天然契合，多选/成组/旋转开箱即用。

### (D) 打印通道（浏览器打印）
| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **@page CSS + HTML（推荐）** | 零驱动、跨平台、所见即所得 | 受浏览器边距/分页限制 |
| Puppeteer 服务端转 PDF | 精确、脱离浏览器 | 重、需 Chromium |

> **推荐**：浏览器通道用 `@page` 精确设置标签宽高；需要精确矢量归档时走 `ImageProvider`（pdf-lib）。
