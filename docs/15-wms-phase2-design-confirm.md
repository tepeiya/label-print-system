## 1. 工单状态机（建议方案）

```
                 ┌──────── CANCEL（仅 CREATED/RELEASED）────────┐
                 │                                              ▼
CREATED ──RELEASE──▶ RELEASED ──ISSUE_START──▶ ISSUING ──ISSUE_DONE──▶ ISSUED ──CLOSE──▶ CLOSED
   │                    │                         │                      │
   └────EDIT（改行）─────┘                    ──FAIL/部分发料──▶  缺料挂起（ISSUING 保留，记录缺料行）
                                                                        │
                                              ──RETURN（退料，阶段二内）──┘（ISSUED→ISSUING 冲销，需审批）
```

**合法流转表**

| 当前状态 | 允许的下一状态 | 触发动作 | 守卫 |
|---|---|---|---|
| CREATED | RELEASED / CANCELLED | 下发 / 取消 | 明细行非空 |
| RELEASED | ISSUING / CANCELLED | 开始发料 / 取消 | 已做齐套检查（可缺料，记录缺料清单） |
| ISSUING | ISSUED / (保持) | 发料完成 / 部分发料 | 所有行发料量达标或人工放行 |
| ISSUED | CLOSED / ISSUING(退料) | 关单 / 退料 | 关单需无未结退料；退料需审批 |
| CLOSED | — | 终态 | 不可回退 |
| CANCELLED | — | 终态 | 不可回退 |

> 请确认：①是否接受该状态机？②"缺料挂起"是否需要独立状态 `SHORTAGE`（否则用 ISSUING + 缺料标记）？③退料是否必须在阶段二（也可延后阶段三）？

## 2. BOM 展开与齐套口径（复用现有 `computeKit`）

- **展开**：复用 `InventoryService.checkKit` → `computeKit`。同一产品最多一个 `active` BOM（现有约束）。
- **需求量公式**（现有实现，建议沿用）：`单位需求 = qtyPer × (1 + lossRate)`，`总需求 = round3(单位需求 × demand)`，**损耗率按 BOM 行计入需求**（不是按发料额外追加）。
- **齐套率**：按行取 `maxSets = floor(available / 单位需求)`，齐套率 = `min(maxSets, demand) / demand`；缺料行 = `shortage > 0`。
- **替代料**：见决策 2。
- **降级行为**：BOM 不存在 / 无明细行 → 现实现返回 0 行齐套（不报错，友好摘要）；阶段二需确认"无 BOM 的工单是否允许下发"。

## 3. 发料过账事务与补偿（复用阶段一 T4 已验证语义）

沿用阶段一实证的补偿模型，**不做分布式事务**：

1. **顺序**：库存变更（`InventoryGateway` 扣减，带幂等键 `ISSUE:WO{no}:{line}`）→ 发行状态更新 → 发料记录落库 → 标签打印（旁路，失败记 failed、可补打）。
2. **失败语义**：库存变更在第一步，失败后行状态/发料记录均不落库（**无脏数据**）；靠幂等键 + "发料记录是否存在"作为完成标志，人工/上游重跑同一单据可幂等收敛（不重复扣库存、不重复建发料记录）。
3. **承诺口径**：对客户表述为"失败后单据无脏数据、重跑可幂等收敛"；**不是**"系统自动重试到最终一致"（自动重试需 BullMQ 队列，阶段二可选）。
4. **库存落点**：发料扣减按批次维度（`StockBatch` 已有 batch_no/location_id）；指定批次见决策 5。

## 5. 阶段二范围边界（建议）

- **做**：工单（手工/Excel 建单）、BOM 展开与齐套检查、发料任务、发料过账（扣库存 + 批次标签）、退料、缺料清单。

- **PDA 前端**：与阶段一同属独立排期（H5 + zxing-wasm），阶段二后端 API 先行。
