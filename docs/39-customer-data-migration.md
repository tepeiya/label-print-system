# 39 · 客户数据迁移作业指导书

> 配套工具：`tools/data-migration/`（命令与字段说明见该目录 README）。本文是"到了客户现场怎么干"的顺序与判据。

## 1. 迁移到底迁什么

| 迁 | 不迁 |
|---|---|
| 物料主数据（含多档 GTIN / 箱规） | 历史单据流水（收货、出库、发料记录） |
| 期初库存余额（按批号/库位） | BOM 结构（在系统里建，或单独立项） |
| 未关闭的工单（含配料明细） | 自定义字段定义（先在系统建字段） |
| 待收货的收货单 | 财务、客户、供应商档案（系统未覆盖） |

判据：**迁移后客户能"扫得进、打得对、发得出"**，而不是把旧系统的每一行都搬过来。历史流水留在旧系统只读即可，硬导会把期初和流水搞成两套账。

## 2. 现场顺序（半天到一天）

1. **建环境**：`deploy/init.sh`，`.env` 里 `SEED_DEMO=0`。
2. **先建仓库与库位**：这是迁移的前置数据，工具不会替你造仓库（编码错会导致整批中止）。编码规则提前和客户确认，改一次成本很高。
3. **拿模板**：`node tools/data-migration/import.mjs --template ./migration`，把 `labelflow-迁移模板.xlsx` 发给客户。
4. **客户填表**，你跑 `--check` 出报告，来回改到 0 错误。这一步通常在客户办公室做，比在系统里逐条改快 10 倍。
5. **干跑**：`--apply ... --dry-run`，确认仓库/库位/物料引用都对得上，再真跑。
6. **真跑**：`--apply`，看四类结果汇总，把 `reports/导入结果-*.json` 存档（客户签字时附上）。
7. **验收抽样**：随机抽 3 个物料核对编码/箱规；抽 3 个批号核对数量；打开一张工单看配料是否齐。

## 3. 期初库存的口径

工具走的是 `库存调整单(GAIN) → 过账`，不是直写库存表。原因：

- 流水里有单号、操作人、原因，客户审计时说得清；
- 期初一次性进账，之后所有变动都有单据，账实能对；
- 出问题可以按单撤销（`POST /inventory/adjustments/:id/cancel`，未过账前）。

**数量口径**：填客户盘点表上的实物数量，不是旧系统账面数量。差异让客户先在自己的盘点表里解释，别把旧系统的错账带进来。

**重复防护**：同文件指纹 + 已有余额两种判断，任一命中就跳过该行。真要重导修正，先做盘点调整，别用 `--force-stock` 硬灌 —— 那会让库存翻倍。

## 4. 失败怎么处理

| 工具输出 | 含义 | 处理 |
|---|---|---|
| `前置检查未通过`，未写入 | 仓库/库位编码不存在 | 改模板编码或先在系统建仓库，重跑 |
| `物料 ... 失败 [400] ...` | 编码重复/GTIN 被占用/字段超长 | 按报错改该行；GTIN 被别的物料占用时找客户确认归属 |
| `期初 ... 物料不存在` | 物料没建成功 | 先修物料，再单独跑期初（工具支持只传 02 表） |
| `工单 ... 没有启用中的 BOM` | 没填明细也没 BOM | 补 `05_工单明细`，或把 03 表"按BOM展开"改为否 |
| `单号已存在，跳过` | 上次跑到一半 | 去系统里核对那张单的明细行数；不全会导致收不上货，必要时删单重导 |

原则：**失败行不改就别重跑整批**——物料和期初有幂等保护，工单/收货单靠单号识别，重跑是安全的，但要读懂"跳过"和"失败"的区别。

## 5. 交付时的三份记录

1. `reports/校验报告-*.csv`（客户填错什么、改了什么）
2. `reports/导入结果-*.json`（最终每类成功/跳过/失败数，附指纹）
3. 抽样核对表（3 物料 + 3 批号 + 1 工单，客户签字）

## 6. 已知限制

- 单批物料没有上限（逐条请求，几千条分钟级）；收货单每单 ≤1000 行（服务端限制），工单每批 ≤200 张（工具自动分批）。
- GTIN 只接受 8~14 位数字并校验末位；客户给的是条码图片时，要先解码再填，别手写。
- 工具不校验"客户业务上是否该这么建"（比如一个物料该有几档箱规），这属于实施顾问的判断。
- 本次实测在 PostgreSQL 14 + 单库模式完成；多租户独立库（dedicated）场景未实测，独立库租户请先在测试实例验证一遍。
