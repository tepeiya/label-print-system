# LabelFlow 客户数据迁移工具

把客户现有的 Excel 台账搬进系统，不靠人肉敲。三件事：**给模板、离线查错、带审计导入**。

```bash
cd tools/data-migration

# 1) 生成模板（含 00 说明 + 4 张数据表）
node import.mjs --template ./migration

# 2) 客户填完，先离线校验（不连服务器，出错给 CSV 报告）
node import.mjs --check ./migration/客户数据.xlsx

# 3) 校验干净后导入
node import.mjs --apply ./migration/客户数据.xlsx \
  --base http://127.0.0.1:3200/api/v1 \
  --user admin --pass '改过的密码' --tenant default
```

无第三方依赖：Excel 读写在运行时复用 `backend/node_modules/xlsx`。单独使用可 `npm i`（`package.json` 已声明）。

## 数据表

| 表 | 内容 | 关键规则 |
|---|---|---|
| `01_物料` | 编码、名称、规格、单位、类别、安全库存、UDI、单件/箱/托 GTIN + 箱规、默认仓库/库位 | GTIN 校验位必须对；箱/托档必须同时填数量；同表 GTIN 不可重复 |
| `02_期初库存` | 物料、仓库、库位、批号、数量 | 走库存调整单（GAIN）+ 过账，有审计有操作人；**已有余额的行自动跳过，防重复翻倍** |
| `03_工单` | 工单号（可空）、产品、需求数量、仓库、优先级、计划开工、按BOM展开 | 产品无 BOM 时"按BOM展开"不能填是 |
| `05_工单明细` | 工单号、物料、需求数量、批号 | 按工单号挂到 03 表；不填则工单没有配料，客户无法发料 |
| `04_收货单` | 收货单号、仓库、物料、预计数量、批号 | 同一单号多行 = 一张单多条明细 |

列名不要改；整行以 `#` 开头视为说明行，导入时忽略（模板里的示例行就是这个形式）。

## 行为约定

- **有错误默认拒绝写入**（退出码 2）。`--force` 才会带错继续，不建议。
- **重复执行安全**：
  - 物料：按编码匹配，已存在则跳过；`--update` 才用 PUT 覆盖（含 GTIN 档位，会整体替换）。
  - 期初：同文件指纹且已过账 → 跳过；不同文件但该物料/仓库/批号**已有余额** → 逐行跳过并提示。
  - 工单/收货单：单号已存在 → 跳过并提示（不当作失败）。
- **前置预检**：所有引用的仓库/库位编码先在系统里查一遍，不存在直接中止，不会"建了物料才发现仓库编码错"。
- `--dry-run`：连服务、登录、前置检查都做，但不写任何数据，适合客户现场先演一遍。
- 每类数据都有行级结果，最终写 `reports/导入结果-<指纹>.json`；失败不中断后续类别（物料失败会导致依赖它的期初/工单失败，属预期）。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 校验/导入无错误（含"全部跳过"的幂等重跑） |
| 1 | 参数或文件问题 |
| 2 | 校验有错误、前置检查未通过，或导入有失败项 |

## 实测记录（2026-11-26，本次提交前）

在 Ubuntu 22.04 + PostgreSQL 14 + redis 的干净库（`db-init.sh --seed-demo`，92 张表）上跑通：

| 场景 | 结果 |
|---|---|
| 模板生成 | 5 个 sheet，示例行以 `#` 开头被正确忽略 |
| 故意错数据校验 | 7 条错误全部命中（GTIN 校验位、重复编码、箱规缺数量、编码为空、负库存、需求数量 0、安全库存负数），退出码 2 |
| 干净数据全链路 | 物料 2 新建（含 UNIT + CARTON 两档 GTIN）→ 期初 2 行过账（100 / 30.5）→ 工单 1 张 → 收货单 1 张 2 行，退出码 0 |
| 幂等重跑 | 物料跳过 2、期初跳过（余额 200/61 未翻倍）、工单"已存在"跳过、收货单 409 跳过，退出码 0 |
| 工单明细 | WO-MIG-003 带 2 行配料落库，`qty_required` 与批号正确 |
| 前置预检 | 故意用 `A-01-01`（系统里实际是 `DEMO-A01`）→ 中止且未写入任何数据 |
| 只补工单 | 缺 01 物料表 → 警告跳过物料，工单照常导入 |

## 不做的部分（诚实说明）

- **不导 BOM**：BOM 结构需在系统里建（或用后续的 BOM 导入）；工单可走"按BOM展开"或 05 明细。
- **不导历史单据**（收货/出库流水）：只导主数据和期初余额。历史单据属于归档，建议留在旧系统只读。
- **不导自定义字段定义**：01 表只导 `customFields` 之外的标准字段；自定义字段需先在系统里建字段，再扩展模板。
- 期初库存只能"加"。客户若已手工建过账再重跑，余额检查会拦住，但**修正错误数量要靠盘点单**，不是再次导入。

完整交付流程（含现场操作顺序与验收）见 `docs/39-customer-data-migration.md`。
